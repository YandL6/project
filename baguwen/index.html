一、计算机基础

1.1 操作系统

Q1进程和线程的区别？协程又是什么？

进程是资源分配的基本单位，拥有独立的虚拟地址空间、文件描述符表等；线程是 CPU 调度的基本单位，同进程内的线程共享地址空间和资源，只拥有自己的栈、寄存器和程序计数器。

  • 隔离性：进程间隔离（一个进程崩溃不影响其他进程），线程间不隔离（一个线程段错误可能带崩整个进程）
  • 切换开销：进程切换需切换页表（TLB 失效）、换内核栈，开销大；线程切换只保存寄存器和栈指针，开销小得多
  • 通信方式：进程间需 IPC（管道/消息队列/共享内存/信号量/socket）；线程间直接读写共享变量 + 同步原语（锁/条件变量）
  • 协程：用户态的轻量"线程"，切换不陷入内核（无需系统调用），由程序自己调度（如 Go 的 goroutine、Python 的 asyncio）。代价是协程内不能有阻塞调用，否则会卡住整个线程

追问高频：为什么有了多线程还要多进程？——隔离与安全（如 Chrome 每个标签页一个进程）；Python GIL 导致多线程无法并行 CPU 密集任务，要用多进程或协程。

Q2进程间通信（IPC）有哪些方式？各自适用场景？
  • 管道（pipe）：半双工，单向字节流，父子进程间用；命名管道（FIFO）允许无亲缘关系进程
  • 消息队列：内核中的消息链表，按类型收发，有格式边界，独立于收发进程生命周期
  • 共享内存：两进程映射同一块物理内存，最快的 IPC（零拷贝），但必须配信号量等同步机制防止竞争。大数据量传输首选
  • 信号量：主要用于同步（P/V 操作），而非传数据
  • 信号（signal）：异步通知机制，如 SIGKILL、SIGSEGV
  • Socket：唯一可跨主机的 IPC，本地可用 Unix Domain Socket（比 TCP socket 快，不走网络协议栈）

面试要点：共享内存为什么快——数据不需要在内核态和用户态之间来回复制，一次映射后直接读写；管道则每次 write/read 都要陷入内核并拷贝两次。

Q3死锁产生的四个必要条件？如何预防和避免？

四个必要条件（缺一不可，打破任一即可破死锁）：

  1. 互斥：资源一次只能被一个进程持有
  2. 持有并等待：进程持有资源的同时等待别的资源
  3. 不可剥夺：资源不能被强行抢走
  4. 循环等待：进程间形成环形等待链

预防：一次性申请所有资源（破坏 2）；资源可抢占（破坏 3）；按全局顺序加锁（破坏 4，工程上最常用，如规定所有锁按 id 升序获取）。

避免：银行家算法——分配前判断系统是否仍处于安全状态。工程上更常见的是检测+恢复：超时放弃锁、死锁检测线程杀掉牺牲者。

实际写代码层面：std::lock(mtx1, mtx2) 一次性锁多个锁避免顺序死锁；try_lock + 退避重试。

Q4什么是虚拟内存？页缺失有哪些类型？页面置换算法？

虚拟内存：给每个进程一个独立、连续的假象地址空间，通过页表映射到物理内存/磁盘。作用：进程隔离、按需分配（程序可以大于物理内存）、简化内存管理。

  • 页缺失类型：① 硬缺页（页在磁盘，需 IO，代价 ~ms 级）② 软缺页（页在内存但没建立映射，如写时复制 COW 触发）③ 无效缺页（非法访问 → 段错误）
  • 写时复制（COW）：fork 后父子共享物理页，标记只读，谁写谁触发缺页再复制——fork 快的原因
  • 置换算法：FIFO（可能 Belady 异常）、LRU（近似实现：时钟/二次机会算法，硬件只给访问位）、LFU、OPT（理论最优，不可实现，用于对比）

延伸：TLB 是页表的 cache；多级页表解决页表本身太大的问题；大页（HugePage）减少 TLB miss——推理服务部署常用 2MB 大页提升性能。

Q5用户态和内核态？什么操作会导致切换？

用户态：只能访问受限指令和自己的地址空间；内核态：可执行特权指令、访问所有硬件。切换由系统调用、中断、异常触发。

切换成本高：保存/恢复寄存器、切换内核栈、页表隔离（KPTI）下还要切 CR3，一次系统调用约 1~几 μs。这就是零拷贝、epoll、io_uring 等优化的动机——减少陷入内核的次数和数据在内核/用户态之间的拷贝次数。

Q6select / poll / epoll 的区别？为什么 epoll 快？

三者都是 IO 多路复用：一个线程监听多个 fd 的就绪事件。

selectpollepoll
fd 上限FD_SETSIZE=1024无硬限制无（受系统内存）
fd 传递每次调用全量拷贝进内核同左注册一次（epoll_ctl），事件发生时内核回调挂入就绪链表
就绪查找O(n) 线性扫描O(n)O(1) 直接取就绪链表（epoll_wait）
触发模式LTLTLT / ET（边缘触发，需非阻塞 fd + 一次读干净）

epoll 快的本质：把"每次注册+全量扫描"变成"注册一次 + 事件驱动回调"，活跃 fd 多时优势缩小，活跃 fd 少而监听 fd 多时（典型：长连接网关）优势巨大。

追问：ET 和 LT 的区别？ET 只在状态变化时通知一次，必须一次性读完（循环 read 直到 EAGAIN），否则剩余数据不再通知；LT 只要缓冲区有数据就持续通知，编程简单但可能重复唤醒。

Q7互斥锁、自旋锁、读写锁的区别与选择？
  • 互斥锁（mutex）：拿不到就睡眠，让出 CPU。临界区较长、持锁时间不确定时用，上下文切换成本 ~μs
  • 自旋锁（spinlock）：拿不到就忙等（循环 CAS）。临界区极短（几十 ns 级）时反而省了睡眠/唤醒两次切换；内核/中断上下文只能用它（不能睡眠）
  • 读写锁：读共享、写独占。读多写少场景提升并发；注意写者可能饿死（需写优先版本）
  • RCU：读端几乎零开销（不加锁），写端复制后原子切换指针、延迟释放旧版本——适合读极多写极少的数据结构

经验法则：持锁 < 两次上下文切换的成本（约 1~2μs）→ 自旋更划算；否则睡眠锁。CAS 无锁结构适合极短操作但要注意 ABA 问题。

1.2 计算机网络

Q8TCP 和 UDP 的区别及各自适用场景？

TCP：面向连接、可靠传输（确认+重传+排序）、流量控制（滑动窗口）/ 拥塞控制、字节流（无消息边界）、点对点。头部 20B+。

UDP：无连接、尽力而为、数据报（有边界）、支持一对多广播/组播。头部 8B，开销小延迟低。

  • TCP 适用：HTTP/文件传输/数据库连接——不能丢的场景
  • UDP 适用：音视频（丢几帧无妨，延迟敏感）、DNS 查询、游戏、QUIC（在 UDP 上自己实现了可靠传输，绕开 TCP 内核栈的历史包袱 + 支持连接迁移）

追问：视频会议为什么不用 TCP？——TCP 队头阻塞 + 重传放大延迟，实时性优先于完整性，宁可丢帧；且弱网下 TCP 拥塞控制会主动降速，画质雪崩。

Q9三次握手过程与每一步的作用？为什么不能两次？
Client            Server
  | ---- SYN (seq=x) ----> |   ①客户端进入 SYN_SENT
  | <-- SYN+ACK (seq=y, --> |   ②服务器进入 SYN_RCVD
  |        ack=x+1)        |
  | ---- ACK (ack=y+1) --> |   ③双方 ESTABLISHED

为什么三次：核心是双方都要确认"我的发送和接收能力都正常"。两次握手时，服务端无法确认自己发出的 SYN 被收到；且历史重复的 SYN（旧连接的迟到报文）会让服务端单方面建立连接、白耗资源——经典"陈旧连接请求"问题。

四次挥手中 TIME_WAIT 为什么等 2MSL：① 确保最后一个 ACK 能到达对方（丢了对方会重传 FIN，我还能再回 ACK）；② 让本连接的旧报文在网络中自然消亡，避免污染新连接。TIME_WAIT 在主动关闭方，持续 1~4 分钟，高并发短连接服务器的经典问题（解法：长连接复用、tcp_tw_reuse、负载均衡）。

Q10TCP 如何保证可靠传输？拥塞控制四阶段？

可靠性机制：序列号 + 确认应答（累计 ACK）、超时重传（RTO 自适应）、快速重传（3 个冗余 ACK）、滑动窗口流量控制（接收方通告 rwnd）、校验和、按序交付去重。

拥塞控制（针对网络，区别于流量控制针对接收方）：

  1. 慢启动：cwnd 从 1 MSS 起，每 RTT 翻倍（指数增长）到 ssthresh
  2. 拥塞避免：超过 ssthresh 后每 RTT +1 MSS（线性，AIMD）
  3. 拥塞发生：超时 → ssthresh = cwnd/2，cwnd 重置为 1，重新慢启动（剧烈）；3 个冗余 ACK → 快速恢复：cwnd 减半后线性增长（温和）
  4. 快速恢复：配合快速重传的过渡状态

现代默认 CUBIC（Linux），Google 的 BBR 改为主动测量带宽和 RTT、不依赖丢包信号，长肥管道（高带宽高延迟）下吞吐显著更好——大模型推理服务的流式输出也受益于此。

Q11HTTP 1.1 / 2 / 3 的演进？HTTPS 握手过程？
  • HTTP/1.1：长连接（keep-alive）、管道化（但队头阻塞）、Host 头支持虚拟主机、Chunked 分块传输
  • HTTP/2：二进制分帧、多路复用（一个 TCP 连接上并发多个流，解决 HTTP 层队头阻塞，但 TCP 层丢包仍会阻塞所有流）、头部压缩 HPACK、服务器推送
  • HTTP/3：底层换成 QUIC（UDP）——流之间真正独立（丢包只影响所在流）、0-RTT 建连、连接迁移（用 Connection ID 而非四元组，WiFi 切 4G 不断连）

HTTPS（TLS 1.2 RSA 握手）要点：① ClientHello（支持的密码套件、随机数）② ServerHello + 证书（含公钥）③ 客户端验证证书链（CA 签名、域名、有效期）→ 生成预主密钥用服务器公钥加密发送 ④ 双方基于三个随机数派生会话密钥 ⑤ 之后对称加密通信。非对称只用于交换密钥，数据传输用对称（性能）。TLS 1.3 握手减为 1-RTT，且删掉了不安全套件。

Q12从输入 URL 到页面展示，中间发生了什么？（经典串讲题）
  1. DNS 解析：浏览器缓存 → 系统缓存 hosts → 本地 DNS（递归）→ 根/顶级/权威（迭代），拿到 IP
  2. TCP 三次握手（HTTPS 再加 TLS 握手）
  3. 发送 HTTP 请求：应用层构造请求 → 传输层分段 → 网络层 IP 路由（ARP 找下一跳 MAC）→ 链路层帧 → 经过 NAT、路由器转发
  4. 服务器侧：负载均衡（LVS/Nginx）→ 应用服务器（可能查 Redis 缓存、读数据库、RPC 调下游）→ 返回响应
  5. 浏览器渲染：解析 HTML 建 DOM 树、CSS 建 CSSOM、合成渲染树 → 布局（reflow）→ 绘制（repaint）→ 合成层上屏；期间 JS 可能阻塞解析（defer/async）
  6. 连接复用或关闭（keep-alive / 四次挥手）

这题是"知识串联题"：面试官可以任意一层往下钻（DNS 用 UDP 还是 TCP？ARP 是什么？为什么 reflow 比 repaint 贵？），每一环都要能展开。

1.3 数据库与缓存

Q13MySQL 为什么用 B+ 树做索引？和 B 树 / 哈希 / 红黑树对比？
  • vs B 树：B+ 树非叶子节点不存数据只存键 → 单页能放更多键 → 树更矮（3~4 层支撑千万级数据）→ 磁盘 IO 次数更少；叶子节点用链表串联 → 范围查询/排序顺着链表扫即可，B 树要中序回溯
  • vs 哈希：哈希等值查询 O(1) 但不支持范围查询和排序，无法用最左前缀；Memory 引擎支持哈希索引
  • vs 红黑树/AVL：二叉树太高（log₂(10⁷)≈23 次节点访问 ≈ 23 次磁盘 IO），B+ 树一个节点一页（16KB），一次 IO 拿一整页

聚簇 vs 二级索引：聚簇索引叶子存整行数据（InnoDB 主键即聚簇）；二级索引叶子存主键值 → 查非索引列需回表；覆盖索引（查询列都在索引里）可免回表——EXPLAIN 里 Extra 出现 Using index 即覆盖。

最左前缀原则：联合索引 (a,b,c) 只能命中以 a 开头的查询；WHERE b=x 用不上该索引。索引列参与函数/隐式类型转换/前导 % LIKE 会导致索引失效。

Q14事务 ACID 与隔离级别？MVCC 怎么工作？

ACID：原子性（undo log 回滚）、一致性（目的）、隔离性（锁+MVCC）、持久性（redo log）。

并发问题与隔离级别：

隔离级别脏读不可重复读幻读
读未提交 RU✔会发生✔✔
读已提交 RC✘✔✔
可重复读 RR（InnoDB 默认）✘✘基本避免（间隙锁）
串行化✘✘✘

MVCC：每行隐藏字段 trx_id（最后修改事务）+ roll_pointer（指向 undo log 旧版本，构成版本链）。读时生成 ReadView（活跃事务列表），判断版本链上哪个版本对自己可见：RC 每次查询生成新 ReadView（所以能看到别人已提交的最新数据），RR 只在第一次查询生成（所以可重复读）。普通 select 是快照读不加锁，update/insert/delete 是当前读，当前读用行锁+间隙锁（Next-Key Lock）防幻读。

Q15Redis 为什么快？缓存穿透 / 击穿 / 雪崩？

快的原因：纯内存 + 单线程命令执行（无锁无上下文切换，IO 多路复用 epoll 串行处理）+ 高效数据结构（SDS 动态字符串、跳表 zset、压缩列表 listpack、渐进式 rehash 的字典）。6.0 引入多线程只用于网络 IO 读写，命令执行仍是单线程。

  • 穿透（查不存在的 key 打到 DB）：布隆过滤器前置拦截 / 缓存空值（短 TTL）
  • 击穿（热 key 过期瞬间大量请求压 DB）：互斥锁重建（只放一个线程回源）/ 热点 key 永不过期+异步更新
  • 雪崩（大量 key 同时过期或 Redis 宕机）：TTL 加随机抖动 / 多级缓存 / 集群高可用 / 限流降级兜底

追问：缓存一致性怎么保证？——主流方案 Cache Aside（读：先读缓存 miss 再读 DB 回填；写：先更新 DB 再删缓存），配合延迟双删或订阅 binlog（Canal）异步删缓存，追求最终一致。

  • 为什么 std::sort 是 introsort：快排 + 递归过深切堆排 +小区间切插入排序，兼顾最坏 O(n log n) 与实际速度
  • 稳定性的意义：多关键字排序（先按 A 稳定排序再按 B）依赖前一关键字次序不被破坏；如成绩排序后按班级再排
  • 外部排序：大文件归并（多路归并 + 败者树 + 置换选择造初始归并段）
  • 非比较排序：计数/基数/桶排序，O(n+k)，突破比较排序 O(n log n) 下界，但有数据范围假设

二、机器学习基础

2.1 基础概念

Q18偏差与方差？欠拟合与过拟合的对策？

偏差：模型假设太简单导致的系统性误差（打靶整体偏移靶心）；方差：模型对训练数据扰动太敏感（换一批数据模型大变）。模型复杂度 ↑ → 偏差 ↓ 方差 ↑，总误差呈 U 型。噪声是数据本身的不可约误差。

  • 欠拟合（高偏差）对策：加特征、加模型复杂度（升阶/加深）、减小正则、训练更久
  • 过拟合（高方差）对策：① 更多数据 / 数据增强 ② 正则化（L1/L2/dropout）③ 早停 ④ 降复杂度（剪枝/减层）⑤ 集成（bagging 降方差）⑥ 交叉验证选模型

K 折交叉验证：K-1 份训练 1 份验证轮转，K 次均值更稳；数据少时用留一法（LOOCV）；类别不平衡要分层抽样保持每折分布一致。注意数据泄漏：归一化统计量、特征选择都必须只在训练折上算。

Q19L1 和 L2 正则的区别？为什么 L1 能产生稀疏解？

L1（|w|₁，拉普拉斯先验）倾向于把不重要的权重压成精确的 0 → 特征选择；L2（|w|²₂，高斯先验）让权重整体变小但不为 0 → 缓解共线性、更平滑。

几何解释：L1 约束区域是菱形，其尖角（顶点在坐标轴上）更容易与损失等高线相切 → 切点落在坐标轴上 → 某些权重恰好为 0；L2 是圆，光滑无角，切点一般不在轴上。

求导视角：L1 的梯度是 ±λ（常数拉力），权重很小时也能被拉到 0；L2 梯度正比于 w（λw），w→0 时拉力也→0，永远拉不到精确 0。

注意：λ 需要调（交叉验证）；先标准化特征再正则，否则尺度大的特征被不公平惩罚。

Q20逻辑回归为什么要用交叉熵而不是 MSE？

两个原因：

  1. 凸性：交叉熵 + sigmoid 组合的损失关于参数是凸的（有全局最优）；MSE + sigmoid 是非凸的（存在局部极小）
  2. 梯度健康：交叉熵的梯度为 σ(z) − y，预测错得越离谱梯度越大、修正越猛；MSE 的梯度带 σ'(z) 项，sigmoid 饱和区 σ'≈0 → 预测极端错误时梯度反而趋近 0，学习停滞

追问链：LR 为什么叫"回归"（本质是线性回归套 sigmoid 做概率映射）；LR 输出的是校准概率吗（是，若模型假设正确，Platt scaling 视角）；多分类用 softmax + 交叉熵，softmax 是 sigmoid 的多类推广。

2.2 经典模型

Q21决策树：ID3 / C4.5 / CART 的分裂准则与剪枝
  • ID3：信息增益 = H(父) − H(子)。缺陷：偏好取值多的特征（极端例子：把"样本 ID"当特征增益最大）
  • C4.5：信息增益比（除以特征自身熵），惩罚多值特征；支持连续特征（二分点扫描）、缺失值
  • CART：分类用基尼指数（=1−Σp²，二阶泰勒近似信息熵，计算更快），回归用平方误差最小化；严格二叉树

剪枝：预剪枝（max_depth / min_samples_split / min_impurity_decrease，可能欠拟合）vs 后剪枝（代价复杂度剪枝 CCP：α·叶数 + 误差 的权衡，更准但更贵）。

单棵树高方差、不稳定 → 随机森林（bagging + 随机特征子集）降方差；→ GBDT（boosting 串行拟合负梯度）降偏差。

Q22GBDT / XGBoost / LightGBM 的演进与高频追问

GBDT：每轮拟合损失函数的负梯度（回归问题即残差），新树输出累加进模型；lr（步长）收缩 + 子采样控制过拟合。

  • XGBoost 的改进：① 目标函数二阶泰勒展开（用一阶+二阶梯度），支持任意二阶可导损失 ② 正则项 Ω = γ·叶数 + ½λ||w||² 直接进目标，推导出最优叶权值和分裂增益公式（gain = ½[G²/(H+λ) + G²/(H+λ) − (G+H)²/(G_L+H_L+λ)] 形态）③ 工程上列块存储支持特征并行、缓存感知、直方图近似分裂点
  • LightGBM 的改进：① 直方图算法（连续特征分桶，从"排序扫描"变"桶统计"）② Leaf-wise 生长（每次分裂增益最大的叶，更深更准但可能过拟合，需 max_depth 限制；XGB 是 Level-wise）③ GOSS 梯度单边采样（大梯度样本全保留、小梯度采样放大）④ EFB 互斥特征捆绑（稀疏特征合并降维）⑤ 原生支持类别特征

高频追问：XGB 怎么处理缺失值（默认方向学习：分裂时尝试把缺失样本划到左右两侧看增益）；GBDT 为什么用回归树做分类（拟合对数几率，再 sigmoid）；boosting 主要降偏差、bagging 主要降方差。

Q23SVM 核心思想与核技巧

硬间隔：最大化离超平面最近样本的间隔（margin = 2/||w||），等价于最小化 ½||w||²。KKT 条件导出支持向量（只有离边界样本决定模型）。

软间隔：引入松弛变量 ξ 与惩罚 C，容忍不可分样本。C 大 → 惩罚违规重 → 间隔窄易过拟合。

核技巧：对偶问题中样本只以内积 ⟨xᵢ,xⱼ⟩ 出现 → 用核函数 K 在低维空间隐式计算高维内积，无需显式升维。常用：线性核（高维稀疏文本首选）、RBF/高斯核（σ 太小过拟合）、多项式核。判定是不是合法核：Mercer 条件（核矩阵半正定）。

对比 LR：LR 损失凸、概率输出、依赖全部样本；SVM 间隔最大化、稀疏解（支持向量）、决策只依赖边界样本。

2.3 优化与评估

Q24SGD / Momentum / Adam 家族？学习率调度？
  • SGD：单/小批量估计梯度。噪声大但泛化常更好；收敛慢、易在峡谷震荡
  • Momentum：v = βv − lr·g，累积历史方向穿越峡谷、抑制震荡；NAG 先按动量走半步再校正
  • AdaGrad/RMSProp：按参数自适应缩放学习率（除以梯度平方的滑动平均），稀疏特征友好
  • Adam = Momentum + RMSProp + 偏差修正。默认首选（β₁=0.9, β₂=0.999）；但泛化高峰常不如精调 SGD（大模型训练多用 AdamW——解耦权重衰减，L2 正则≠权重衰减在自适应优化器中不等价）

调度：warmup（初期大梯度不稳定，线性升温）→ 余弦退火 / 阶梯衰减 / 逆时间衰减。大模型标配：warmup + cosine + AdamW。

Q25AUC 的物理意义？与 PR 曲线怎么选？类别不平衡怎么办？

AUC = 随机取一正一负样本，正样本分数更高的概率（与阈值无关，衡量排序质量——这正是推荐系统的核心诉求）。

  • 计算：rank 法 AUC = (Σ rank(正) − n₊(n₊+1)/2) / (n₊n₋)
  • 不平衡时 ROC-AUC 可能虚高（负样本基数大，FPR 分母大）；PR 曲线更敏感（precision 直接反映正类预测纯度），搜索/推荐等正例稀疏场景看 AUC 同时也要看 PR

类别不平衡对策：① 重采样（过采样小心过拟合——SMOTE 插值生成；欠采样丢信息）② 类权重/损失加权（focal loss：降低易分样本权重，聚焦难样本）③ 换指标（recall@k、MRR、PR-AUC）④ 阈值调整。注意：不要在采样后的数据上评估（评估必须还原真实分布）。

GAUC：按用户分组算 AUC 再按曝光加权平均——消除用户间分数不可比的影响，推荐场景比全局 AUC 更贴近线上。

三、深度学习基础

3.1 训练机制

Q26反向传播的原理？链式法则如何在一层中复用？

前向计算损失，反向沿计算图从输出向输入逐层传递梯度，用链式法则 ∂L/∂x = ∂L/∂y · ∂y/∂x。动态规划思想：中间结果（如 sigmoid 输出、矩阵乘的输入）在前向时缓存，反向复用，避免重复递归计算——这就是框架建计算图 + 自动微分的本质。

计算示例（矩阵层）：Y = XW，∂L/∂W = Xᵀ·∂L/∂Y，∂L/∂X = ∂L/∂Y·Wᵀ。维度检查技巧：梯度形状必与参数形状一致，可用 shape 推导快速验证。

高频追问：为什么深度网络梯度会消失/爆炸（连乘 <1 或 >1 的雅可比）；残差连接为什么能缓解（恒等映射使梯度直通：∂L/∂x = ∂L/∂y·(1 + ∂F/∂x)，恒等项保证至少 1）。

Q27梯度消失/爆炸的原因与全套对策

原因：反向传播是逐层雅可比矩阵连乘；Sigmoid 导数最大 0.25、初始化不当（方差不守恒）等使连乘指数级衰减/放大。RNN 尤其严重（时间维展开等价于极深网络）。

  • 激活函数：换 ReLU 族（正区间导数恒 1）
  • 初始化：Xavier（tanh/sigmoid，方差 2/(fan_in+fan_out)）/ He（ReLU，方差 2/fan_in）——保证各层激活和梯度方差稳定
  • 结构：残差连接（ResNet）、LSTM 门控（细胞状态加性更新，梯度高速公路）
  • 归一化：BN/LN 平滑损失面、允许更大学习率
  • 爆炸专项：梯度裁剪（按范数 rescale，clip norm / clip value）——RNN/Transformer 训练标配
Q28BatchNorm 原理？训练和推理行为为什么不同？为什么有效？

前向：对每个特征通道，用 batch 内统计量归一化 x̂ = (x−μ_B)/√(σ²_B+ε)，再仿射 y = γ·x̂ + β（γ、β 可学习，恢复表达能力）。

训练/推理差异：训练用当前 batch 统计量（所以依赖 batch size、不能逐样本）；推理用训练期统计量的滑动平均（running mean/var）——与 batch 无关，部署确定性行为。

为什么有效：① 缓解内部协变量偏移（ICS，原始论文说法，后续研究认为不完整）② 更主流的解释：平滑损失曲面、允许更大学习率 ③ 带来轻微正则效果（batch 统计量的噪声）。依赖 batch → batch 太小统计量噪声大 → 小 batch / 序列长度可变场景（NLP）用 LayerNorm。

LN vs BN：LN 对单样本所有特征维归一化（与 batch 无关）——Transformer 标配；RMSNorm 是 LN 的简化（除以 RMS，不减均值），LLaMA 等主流 LLM 采用。

Q29激活函数演进：Sigmoid → ReLU → GELU / SwiGLU
  • Sigmoid/Tanh：饱和 → 梯度消失；输出非零中心；计算含 exp 较贵。现只用于门控和输出概率层
  • ReLU：不饱和（正区）、稀疏激活、计算廉价；死区问题（负区梯度 0，大 lr 下神经元永久死亡）→ Leaky ReLU / PReLU
  • GELU：x·Φ(x)，用标准正态 CDF 对输入做概率门控，平滑版 ReLU；BERT/GPT 系列 FFN 激活。直觉：输入越大越可能被"保留"
  • SwiGLU：Swish(xW₁) ⊗ xW₂，门控线性单元——FFN 变三矩阵 (W₁,W₃ 升维、W₂ 降维)，LLaMA/Mistral 等现代 LLM 标配，表达能力更强

追问：为什么激活函数需要非线性（否则多层网络等价于单层线性变换）；输出层为什么一般不接激活（回归）或接 softmax（多分类）。

3.2 结构与组件

Q30CNN 核心概念：卷积、感受野、池化、1×1 卷积
  • 卷积：参数共享（同一核滑全图）+ 局部连接 → 平移等变、参数量骤减；输出尺寸 = (W − K + 2P)/S + 1
  • 感受野：某层一个像素映射回输入的区域大小；堆叠 3×3 卷积比单个大核更优（两层 3×3 感受野 5×5，参数 18W² vs 25W²，且多一次非线性）——VGG 的核心结论
  • 池化：下采样获得平移不变性、扩大感受野、降计算；MaxPool 保纹理、AvgPool 保整体。现代网络常用 stride=2 卷积替代
  • 1×1 卷积：跨通道线性组合（升/降维）、Network-in-Network；Inception/ResNet 的瓶颈层（bottleneck）靠它压通道数降 FLOPs
  • 经典架构一句话：LeNet 开山 → AlexNet ReLU+Dropout+GPU → VGG 深度堆叠 → GoogLeNet 多尺度 → ResNet 残差（152 层的根基）→ 之后 ConvNeXt 用 Transformer 配方改造 CNN
Q31RNN / LSTM / GRU：门控为什么能解决长依赖？

Vanilla RNN：hₜ = tanh(Wₓxₜ + Wₕhₜ₋₁)。时间展开后梯度连乘 Wₕ 的幂 → 谱半径 <1 消失、>1 爆炸。

LSTM 三门：

遗忘门 f = σ(Wf·[h,x])        决定细胞状态保留多少旧信息
输入门 i = σ(Wi·[h,x])        决定写入多少新信息
输出门 o = σ(Wo·[h,x])        决定细胞状态输出多少到 h
Cₜ = f⊙Cₜ₋₁ + i⊙C̃ₜ          细胞状态：加性更新（梯度高速公路）
hₜ = o⊙tanh(Cₜ)

关键：C 的更新是逐元素加法而非矩阵乘法连乘，梯度沿加法路径直通 → 缓解长程梯度衰减。GRU 简化为两门（更新门 z 融合遗忘+输入、重置门 r），参数少 1/4，效果相当。为什么 Transformer 取代 RNN：串行依赖无法并行训练（O(n) 时间步 vs attention 一层并行）、长距离信息要逐步传递（attention 任意两位置直连 O(1) 路径）。

Q32Attention 机制：公式、复杂度、变体
Attention(Q,K,V) = softmax(QKᵀ/√dₖ)·V
  • √dₖ 缩放的原因：QK 内积方差 ~ dₖ（假设 q、k 各维独立零均值单位方差），不除则 logits 方差大 → softmax 进入饱和区 → 梯度极小
  • 复杂度：时间 O(n²·d)、空间 O(n²)（注意矩阵）——序列长度的平方是 LLM 长上下文的根本瓶颈
  • 自注意力 vs 交叉注意力：Q、K、V 同源（decoder）vs Q 来自解码器、K/V 来自编码器（翻译模型）
  • 因果掩码：上三角置 −∞，softmax 后为 0，保证自回归生成不偷看未来
  • 效率变体：稀疏注意力（Longformer 滑窗+全局）、线性注意力（核方法近似 softmax）、FlashAttention（不改数学、IO 感知分块计算省显存带宽——训练加速标配）
Q33Dropout 为什么训练随机丢弃、推理却不丢？

训练：每个神经元以 p 概率失活（前向 mask + 反向梯度同步 mask）→ 等价于训练指数级多子网络的集成 → 降方差防共适应。

推理：不能随机（要求确定性输出）。两种等价处理：① inverted dropout（主流）：训练时除以 (1−p) 预先缩放，推理直接用 ② 原始版：推理时乘 (1−p)。数学本质是保证神经元输出的期望不变。

Transformer 中 dropout 用在：注意力权重、FFN 输出、残差相加后；LLM 时代趋势是少用或不用 dropout（数据量足够大时正则需求低，如 LLaMA 全程不用）。

四、大模型（LLM）

4.1 Transformer 架构

Q34完整走一遍 Decoder-only Transformer 层：数据流与维度

输入 token id (B,L) → embedding 查表 (B,L,d)，加位置信息 → 逐层（以 LLaMA 类为例）：

x = x + RMSNorm(x)                     # Pre-Norm
Q,K,V = xWq, xWk, xWv                  # d→d（GQA 时 K,V 头数更少）
Attn = softmax(QKᵀ/√dₖ + causal_mask)V  # (B,L,L)×(B,L,d)
x = x + Attn·Wo                        # 残差
h  = x + SwiGLU-FFN(RMSNorm(x))        # FFN: W₃( Swish(xW₁) ⊙ xW₂ )
# 下一层重复；最后 RMSNorm + lm_head(d→vocab) → softmax 下一 token 分布
  • 参数量大头：embedding/lm_head（d×V，V≈3~15万）与各层 Wq/k/v/o + FFN 三矩阵。经验比例：FFN 隐层通常 4d（SwiGLU 下约 8/3d 保持参数量）
  • 激活显存为什么是训练的数倍：前向缓存所有中间量供反向，加上优化器状态（AdamW 每参数 2 份 fp32 状态+主副本）。7B 模型 fp16 训练 ≈ 7B×2B(权重) + ×2(梯度) + ×12(优化器+主权重) ≈ 112GB——这就是 ZeRO/LoRA 的动机
Q35为什么除以 √dₖ？为什么要多头？GQA/MQA 又是什么？

√dₖ 缩放：q·k 是 dₖ 个独立分量之和，方差 ≈ dₖ。dₖ 大（64/128）时 logits 波动大 → softmax 高度 one-hot → 梯度近乎 0。除以 √dₖ 把方差拉回 1。

多头：把 d 维拆成 h 个子空间各自做注意力，不同头可学习不同关系模式（句法/共指/位置偏好），最后拼接恢复维度。类比 CNN 的多通道。

KV 头数削减（推理显存优化主线）：

  • MQA（Multi-Query）：所有 Q 头共享 1 组 K/V → KV cache 缩小 h 倍，质量掉得多
  • GQA（Grouped-Query）：Q 头分组共享 K/V（如 32Q:8KV），LLaMA-2/3、Mistral 标配——显存降为 1/4 而质量几乎无损

KV Cache 显存估算：2(K和V) × 层数 × KV头数 × head_dim × 2B(fp16) × batch × seq_len。例：32 层 × 8KV × 128 × 2 × 2B × 8batch × 4k 序列 ≈ 2GB/请求——这就是长上下文贵的原因。

Q36位置编码：正弦 → 可学习 → RoPE / ALiBi

自注意力本身置换不变（打乱 token 顺序结果不变），必须注入位置信息。

  • 正弦编码（原版 Transformer）：固定多频 sin/cos，可外推但效果一般
  • 可学习绝对位置（BERT/GPT-2）：简单有效但不可外推（训练多长就只能多长）
  • RoPE 旋转位置编码（LLaMA/Qwen/Mistral 标配）：把 q、k 向量视为二维复数对，按位置 m 旋转角度 mθ。巧在 q_m·k_n 只依赖相对位置 m−n（旋转保内积），相对位置信息"免费"获得。外推方法：NTK-aware 缩放（改 θ 基频）、YaRN（配合注意力温度修正）——社区主流的 4k→128k 扩展方案
  • ALiBi（BLOOM/MPT）：不编码位置，直接给注意力 logits 加线性距离惩罚 −c·|m−n|，外推平滑、实现最简

追问：为什么 RoPE 能外推而可学习绝对编码不能——RoPE 基于连续函数外推插值，绝对编码对没见过的下标无嵌入向量。

Q37Pre-Norm vs Post-Norm？为什么现代 LLM 全用 Pre-Norm？

Post-Norm（原版）：x = Norm(x + Sublayer(x))。归一化在残差主路上 → 深层梯度衰减、训练不稳，需要 warmup 精细调参。

Pre-Norm（GPT-2 起）：x = x + Sublayer(Norm(x))。残差主干无阻拦——梯度可以沿恒等路径直通任意层，深层训练显著稳定。代价：理论等效深度略降（各层输入未归一）。

折中：DeepNorm、Sandwich-Norm；LLaMA 用 Pre-RMSNorm（去掉减均值，更快）。一句话：Pre-Norm 用轻微的表达力换取百层网络的可训性，是工程正确选择。

4.2 预训练与分词

Q38BPE 分词原理？词表大小怎么权衡？

BPE（Byte-Pair Encoding）训练：① 词切分为字符序列并统计频率 ② 反复合并语料中最高频的相邻对为新 token，直到词表达到目标大小。子词兼顾了 OOV（任何词都能拆成子词/字节）与序列长度（常见词整体成 token）。

  • 变体：WordPiece（BERT，合并准则似然增量）、SentencePiece（语言无关，直接原始文本+空格建模）、Byte-level BPE（GPT 系列，彻底无未知字符）
  • 词表大小权衡：大词表（如 15 万）→ 序列更短（中文友好、上下文装更多）但 embedding/lm_head 参数巨大且稀有 token 训练不足；小词表（3.2 万）→ 序列更长但参数省。多语言/中文模型普遍加大词表
  • 为什么影响成本：中文在英文中心词表下可能 1 字 2~3 token，同样内容 token 数翻倍 → 上下文和推理费用都翻倍
Q39预训练目标：CLM vs MLM？Scaling Law 与数据配比
  • CLM（因果语言建模）：自回归预测下一 token，GPT 系/所有现代 LLM。与生成天然一致、可无限堆积无标注文本；训练时每个位置都有监督信号（teacher forcing）
  • MLM（掩码语言建模）：BERT，随机 mask 15% 预测。双向上下文理解强，但预训练-生成任务不匹配（只预测被 mask 位置，信号稀疏），生成式时代淘汰为主流编码器 Backbone 仍用于 BERT 类检索/分类

Scaling Law（Chinchilla）：给定算力预算，模型参数 N 与训练 token 数 D 应等比例增长（约 D ≈ 20N 达到计算最优）。推论：GPT-3 类"大模型欠训练"不如稍小模型喂更多数据。当代实践（Llama-3）：远超 Chinchilla（重复数据多轮训练），因为推理成本主导——一次性多训练换终身部署便宜。

数据工程（预训练质量决定上限）：去重（MinHash）、质量分类器过滤、毒性过滤、代码/数学数据显著提升推理能力、多语言配比。DeepSeek/R1 证明了高质量数据 + RL 范式的威力。

Q40MoE 混合专家：原理与关键设计

结构：FFN 替换为 N 个专家 FFN + 路由器（gate）。每个 token 由路由器打分，选 Top-K 个专家（K=1~2）计算加权和输出。稀疏激活：总参数量大（如 671B）但每 token 只激活一小部分（如 37B）——"大容量、低算力"。

  • 负载均衡：路由容易坍缩（都涌向少数专家）→ 辅助负载均衡损失（对路由分布加惩罚）
  • 容量因子：每专家 token 上限，超限丢弃——训练吞吐与质量的权衡
  • 共享专家（DeepSeek-MoE）：1~2 个常驻专家承接通用知识，细粒度专家（拆小）提升专业化
  • 部署特点：显存要装下全部参数（除非 offload），适合高吞吐场景；DeepSeek-V3、Qwen-MoE、Mixtral 都是代表

4.3 后训练（SFT / RLHF）

Q41SFT 的细节：模板、loss mask、数据质量

训练形式：指令-回复对，仍用 CLM 损失（下一 token 预测），但只对回复部分的 token 计损失（prompt 部分 loss mask 置 0）——学"怎么答"而不是"复述问题"。

  • 对话模板：特殊 token（<|user|>、<|assistant|>）+ 停止符。模板即"接口协议"——训练与推理模板不一致是效果骤降的常见 bug
  • 数据 > 算法：LIMA 论文（1000 条精标数据对齐效果可观）确立"质量优先"；去重、难度分层、多轮混合、拒答样本配比都影响成败
  • 超参：lr 比预训练小 1~2 个量级（1e-5 级），epoch 2~3 防"背答案"
  • 通用 SFT vs 领域 SFT：领域数据晚加、小 lr、混通用数据防能力遗忘（灾难性遗忘的对冲）
Q42RLHF 三阶段：PPO 的完整流程
  1. SFT：监督微调得到对话基座
  2. 奖励模型（RM）训练：同一 prompt 生成多个回复，人工排序 →Bradley-Terry 成对损失 L = −log σ(r(x,y_w) − r(x,y_l))。RM 通常用基座去掉 lm_head 换标量头
  3. PPO 优化：策略 = 当前 LLM。目标 = E[r(x,y)] − β·KL(π‖π_SFT)
    • 4 个模型在线：actor（训练）、critic（价值）、reward（冻结）、ref（SFT 副本算 KL，防奖励作弊/模式坍缩）
    • 偏差修正：GAE；KL 惩罚常实现为 ref 模型 logit 差加进 reward

PPO 痛点：4 模型并行显存爆炸、训练超参敏感、在线采样慢——催生了 DPO 等离线方法。

Q43DPO 为什么能绕开奖励模型？GRPO 的创新？

DPO：数学上可证明"最优策略 = reward + KL 约束"有闭式解，奖励可用策略与 ref 的对数比重写。代回 BT 损失得到直接在策略上的损失：

L_DPO = −log σ( β·[log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)] )

偏好对直接训 LLM，无 RM、无 PPO 采样循环，稳定省资源。代价：离线（数据分布外退化）、易过拟合偏好对、β 难调。适合资源有限的中等规模对齐。

GRPO（DeepSeekMath/R1）：去掉 critic（价值网络），用组内相对奖励：同一 prompt 采 G 个回复，advantage = (r − mean(group)) / std(group)。配规则奖励（答案对错、格式合规）替代神经 RM——DeepSeek-R1 展示了纯 RL（无 SFT 冷启动的 R1-Zero）能自发涌现长链推理、反思与"顿悟"。衍生趋势：可验证奖励（RLVR）在代码/数学上成为主流。

Q44什么是涌现能力？CoT 与推理模型？

涌现：某些能力（多步推理、指令泛化、ICL）在小模型上接近随机，跨过某规模阈值后陡然提升——也伴随争议（是否是度量伪影）。

  • CoT（思维链）：让模型"一步步想"，把多步推理摊到 token 序列上，缓解单步前向计算的深度限制
  • 推理模型（o1/R1）：RL 训练模型自主生成长 CoT——自我验证、回溯、多路径探索；测试时计算（test-time compute）换准确率：推理预算越长分数越高
  • 与普通 chat 模型的部署差异：输出 token 数多 10~100 倍 → 推理成本与延迟主导；需要更强的 KV cache 与吞吐优化

4.4 高效微调与推理

Q45LoRA 原理：为什么低秩有效？超参怎么选？

核心假设：微调引起的权重变化 ΔW 是低秩的（任务适配方向集中于少数子空间）。于是 ΔW = BA，B∈R^(d×r), A∈R^(r×k)，只训 r ≪ min(d,k) 的小矩阵：

h = xW₀ + (α/r)·x·B·A     # W₀ 冻结；A 高斯初始化、B 零初始化（起点=原模型）
# 约减后仍有 γ 扰动时：h = γxW₀ + xBA   # 更稳定（rsLoRA 等）
  • 训练显存：7B 模型 LoRA r=16 可在单张 24GB 卡训练（全参需百 GB 级）
  • 超参经验：r = 8~64（任务越复杂/数据越大越高）；α 常取 2r 或 r；作用位置：q,v 起步，全线性层（q,k,v,o+FFN）效果更好；学习率比全参高一个量级（1e-4 级）
  • QLoRA：基座 NF4 量化冻结 + LoRA 训练，单卡 48GB 微调 65B；合并：BA 可在部署时加进 W₀，零额外推理开销
  • 对比其他 PEFT：Prompt/Prefix Tuning 改输入侧（难训、效果弱）；Adapter 加层（有推理延迟）；LoRA 是质量/成本平衡最优解
Q46推理优化全景：KV Cache → 量化 → PagedAttention → 投机解码

自回归生成的两大阶段：Prefill（并行处理整个 prompt，算力密集，决定首 token 延迟 TTFT）与 Decode（逐 token，每步重算全部 K/V——KV Cache 把历史 K/V 存下来，每步只算新 token 的 QKV，显存带宽密集，决定吞吐 TPOT）。

  • 量化：W8A8（INT8 权重+激活，几乎无损）、W4A16（GPTQ/AWQ 权重量化，显存减 4 倍，速度受限于反量化）；AWQ 按激活分布保护显著权重通道。注意 KV Cache 也可量化（KV INT8/FP8）
  • 连续批处理（continuous batching）：不同请求不同长度动态进出 batch，GPU 利用率数倍提升——vLLM 的核心之一
  • PagedAttention（vLLM）：KV Cache 分页管理（类似操作系统虚拟内存），消除预留最大长度的碎片，显存利用率 >90%，支持 prefix cache 共享（相同 system prompt 复用 KV）
  • 投机解码：小模型（draft）快速猜 k 个 token，大模型一次并行验证，接受的部分全部白嫖——数学上保证与大模型分布一致；变体：Medusa 多头预测、EAGLE、自投机（复用层）
  • 并行：张量并行 TP（切权重维度，通信大，适合单机多卡 NVLink）、流水线并行 PP（切层，带宽友好）、专家并行 EP（MoE 专用）；serving 层面的数据并行多副本 + 负载均衡

面试常算：给 A100 80GB、7B fp16 模型（14GB 权重），能装多大 batch × 上下文？——预留权重 + 激活，剩余给 KV Cache 按 Q35 公式算。

4.5 RAG 与评测

Q47RAG 完整链路与每一环的优化

离线：文档解析（PDF/HTML/表格）→ 切块 → 向量化（embedding 模型）→ 向量库；在线：query 改写 → 检索（向量 + BM25 混合）→ 重排（cross-encoder）→ 拼 prompt → 生成（带引用）。

  • 切块：固定大小会切断语义；用标题层级 + 重叠窗口（overlap 10~20%）；表格/代码单独结构化
  • 检索：向量检索语义泛化强、BM25 精确词匹配强 → 混合检索 + RRF 融合；query 改写（HyDE：生成假设答案再检索、多查询扩展）显著提升召回
  • 重排：bi-encoder 召回 top-100 → cross-encoder（query-doc 联合编码）精排 top-5；重排器贵但准
  • 高级：GraphRAG（实体关系图谱 + 多跳检索）、Agentic RAG（检索作为工具由 Agent 决定查什么、查几轮）
  • 评测：检索端 recall@k、MRR；生成端忠实度（faithfulness：答案是否被检索内容支撑）+ 答案相关性（RAGAS 框架）

RAG vs 微调选型：知识频繁更新/需引用溯源 → RAG；改风格/格式/领域语感 → 微调；两者正交可叠加（微调 embedding + 微调生成器）。

Q48幻觉的成因与缓解？主流评测基准？

成因：① 训练目标只奖励"像"不奖励"真"（下一 token 概率最大 ≠ 事实正确）② 知识截止/缺失时倾向编造而非承认 ③ 解码随机性（温度）④ 指令遵循压力（用户要答案，模型不倾向拒答）。

缓解：RAG 提供外部证据 + 引用约束；解码降温/约束生成；RLHF 中惩罚编造；评测驱动（幻觉率纳入对齐目标）；系统层面：置信度输出、免责声明、人工审核位。

5.1 系统架构

Q49推荐系统完整链路：召回 → 粗排 → 精排 → 重排

亿级物料不可能全量精排（精排模型一次前向 ~ms 级），所以是漏斗逐层筛：

阶段候选量级延迟预算模型要求
召回百万 → 千全并行（向量 ANN）快、高召回、多路互补
粗排千 → 百~10ms轻量（双塔/小 MLP），与精排一致性
精排百 → 几十~50ms重量级（DIN/多任务），精度优先
重排几十 → 展示~10ms上下文感知、多样性、业务规则
  • 多路召回：向量召回（兴趣）、倒排/标签、热门、协同过滤、关注关系、新品扶持——互补保覆盖
  • 重排的职责：打散同类目、多样性（DPP/滑动窗口）、频控、坑位探索、多目标混排（视频/图文/广告混插——广告是收入的变现位）
  • 为什么不能端到端一个模型：算力约束 + 各层目标不同（召回要"不漏"，精排要"准"，重排要"整体体验"）
Q50搜索、推荐、广告三兄弟的同与不同
  • 搜索：意图明确（query 是强信号）→ 相关性是硬约束（query-item 匹配）→ 排序 = 相关性 × 质量分；难点：语义匹配（query 短、文档长）、冷 query、生成式搜索（LLM 直接生成答案 + 引用）
  • 推荐：无显式意图 → 从历史行为推断兴趣 → 生态目标（时长/留存/多样性），无相关性硬约束但有惊喜度 vs 安全的权衡
  • 广告：三方博弈（用户/广告主/平台）→ 排序分 ≈ pCTR × pCVR × 出价（eCPM），多了机制设计（GSP 竞价、计费逻辑、预算控制）；校准（calibration）极其重要——pCTR 必须是真实概率，竞价才公平

共通内核：全部依赖 CTR 预估技术栈（特征体系 + 深度排序模型 + 多目标）+ A/B 实验文化，所以算法岗 JD 互通。

5.2 召回

Q51双塔模型（DSSM）：结构、为什么不能交互、负采样
user 塔：用户特征（画像+行为序列池化）→ MLP → user_emb (d 维)
item 塔：item 特征 → MLP → item_emb (d 维)
训练：logit = cos(u, v)/τ，softmax + 交叉熵（batch 内负例）
线上：item 塔离线全量算好入库；user 塔在线实时算 → ANN 检索
  • 为什么双塔：item 向量可离线预计算 + ANN 毫秒级检索百万候选。代价是用户和 item 特征在最终内积前不能交互（交互只能各自在塔内）——表达能力受限，这是召回与精排的本质分工
  • 负采样：batch 内其他样本的 item 当负例（方便但流行度有偏，热门 item 被过度当负例）→ 修正：logQ 纠偏 / 流行度降采样；加难负例（同类别、被点击但未转化）提升判别力；in-batch negatives 大 batch 训练是标配
  • 改进：SENet 双塔（动态加权特征）、多兴趣召回（MIND：一个用户多向量）、长序列行为建模

线上 vs 离线不一致问题：离线训练有交叉损失、线上是 ANN 近似检索 + 只取 top——做召回评测要看 recall@k 而非 AUC。

Q52ANN 向量检索：HNSW / IVF-PQ / Faiss 选型
  • 暴力检索：精确但 O(N·d)，百万级以下 + GPU 其实能扛（先算这个基线再谈索引）
  • IVF（倒排文件）：先聚类成 nlist 个簇，查询只扫最近 nprobe 个簇 → 牺牲精度换速度；PQ（乘积量化）：向量切段各自量化成码本，距离用码字近似 → 内存压缩 32~64 倍，有量化误差；IVF-PQ 组合是超大规模（亿级）标配
  • HNSW（分层小世界图）：上层稀疏图快速跳、下层稠密图精确找。查询快、召回高（99%+），但内存大（要存图 + 全精度向量）、构建慢、删除困难
  • 选型：内存充足追求极致召回 → HNSW；亿级 + 内存受限 → IVF-PQ；工程中间态 → HNSW+PQ 混合（Qdrant/Milvus 都支持）

追问：recall@k 怎么测——用暴力检索结果当 ground truth 对比；ANN 的 recall-延迟曲线是核心指标。

5.3 排序模型演进

Q53CTR 模型演进主线：LR → FM → Wide&Deep → DeepFM → DIN
模型核心贡献一句话
LR + 人工特征大规模离散特征工程可解释强但靠人工
FM隐向量两两交叉 xᵢ·xⱼ 内积自动二阶交叉，稀疏友好 O(kn)
FFM字段感知隐向量交叉更细但参数爆炸
Wide & Deep记忆（wide 手工交叉）+ 泛化（deep 嵌入）Google 论文，联合训练
DeepFMFM 替代 wide 部分共享 embedding免人工交叉，端到端
DCN / xDeepFM显式高阶交叉网络（bit-wise / vector-wise）交叉结构化
DIN注意力对用户行为序列建模兴趣多样性 + 与候选相关
DIEN / SIM / BST序列建模升级：兴趣演化 GRU / 长序列检索 / Transformer行为序列是排序最大信息源

DIN 必背：用户历史行为 embedding 按与候选 item 的相关性加权池化（target attention）——候选是泳镜时历史里泳衣权重高、键盘权重低，表达"千人千面 + 一面千兴趣"。面试常问：DIN 的 attention 为什么可以不加 softmax 归一化（保留兴趣强度）。

大模型时代：生成式推荐（把推荐当序列生成，HSTU/行动序列建模）、语义 ID（把 item 离散化成 token 进 LLM）、LLM 做特征/冷启动/可解释性——JD 里"生成式推荐"越来越多，值得准备一页话术。

Q54多任务学习：ESMM / MMoE / PLE

推荐通常同时预估点击、时长、点赞、转化……多任务共用底层。

  • 硬共享：共享底层 + 多头。任务冲突时跷跷板（一升一降）
  • ESMM：解决CVR 样本选择偏差——CVR 只能观察到"点击后"样本（空间偏差）。pCTCVR = pCTR × pCVR，用全空间曝光样本监督 pCTCVR 和 pCTR，pCVR 作为中间变量被间接学出（无偏）
  • MMoE：多个专家网络 + 每 task 一个门控（softmax 加权专家输出）——软性分工缓解冲突
  • PLE：共享专家 + 任务独有专家分离，渐进式路由——解决 MMoE 的负迁移和跷跷板，工业界主流

训练细节：多任务 loss 加权（Uncertainty Weighting 自动学权重 / GradNorm 平衡梯度量级）；离线看各任务 AUC，上线看多目标指标是否跷跷板。

5.4 多任务与机制

Q55特征穿越是什么？怎么防？样本延迟怎么处理？

特征穿越：训练时用了样本发生时刻之后的信息（如"用户当日总点击数"这个统计特征，包含了本条样本之后的点击）→ 离线 AUC 虚高、上线效果崩。所有统计特征必须按时间点快照（point-in-time）。

穿越高发场景：① 聚合统计特征未按天/小时切分版本 ② 用户画像更新时间晚于请求 ③ 样本回流拼接特征时取了最新表而非当时表。

样本延迟（转化延迟）：广告转化可能在点击后数天才发生 → 负样本其实"还没转化"。方案：DFM（延迟反馈模型）建模转化延迟分布；工程上等待窗口 + 重要性采样校正 / 实时假负 + 后续纠正（ES-DFM/FNC）。

曝光偏差：模型只能看到曝光过的 item 的反馈（未曝光无标签）→ IPS（逆倾向得分）用曝光概率加权纠偏。

Q56EE 探索与利用：Bandit / UCB / 汤普森采样 / 冷启动

纯粹利用（只推模型最有把握的）→ 马太效应、新 item 永无出头日；纯探索毁体验。EE 平衡：

  • ε-greedy：ε 概率随机探索（简单粗暴）
  • UCB：score = 均值收益 + c·√(ln N / n_item)——不确定性高的 item 有探索加成（访问少 → 加成大）
  • 汤普森采样：从 Beta 后验采样收益——贝叶斯版 UCB， regrets 理论更优，实现也简单
  • LinUCB：带特征的 UCB（Yahoo! 新闻经典），新 item 也能凭特征先验探索

冷启动：item 侧——内容特征兜底（embedding 泛化 + 探索流量扶持）；user 侧——注册信息 + 热门 + 兴趣选择引导；系统侧——强化时效性（新 item 快速过模型）+ 小流量池。

Q57A/B 实验怎么做才可信？
  1. 分流：按 user_id 哈希分桶（同用户永远同组），正交实验层（不同实验互不干扰）
  2. 样本量计算：给定基线指标、MDE（最小可检测效应）、显著性 α=0.05、功效 1−β=0.8 → 反推所需流量与时长（至少覆盖完整周期——工作日/周末差异）
  3. 显著性检验：比率类 z 检验；注意多重比较问题（看 20 个指标总有一个"显著"——Bonferroni/分层确认）；连续指标看方差与置信区间而不只是均值
  4. 辛普森悖论与 AA 实验：先跑 AA 校验分流均匀；分层看指标防聚合掩盖反向
  5. 护栏指标（guardrail）：主指标涨但崩溃率/延迟/负反馈涨 → 不能上

高阶：交错实验（interleaving，同一次曝光内混两套排序结果，灵敏度比 A/B 高一个量级）；长期留存效应 vs 短期指标的错位（推荐短期时长涨可能透支生态）。

Q58推荐系统常用指标体系
  • 离线模型：AUC / GAUC（用户内排序能力）、LogLoss（校准敏感）、NDCG@k、Recall@k（召回）
  • 在线业务：CTR、时长（总/人均）、留存（次日/7日——终极指标）、互动率（点赞/评论/转发）、多样性（类目熵）、生态指标（创作者发布率/中小作者流量占比）
  • 广告特有：eCPM、ROI（广告主回传）、填充率、CPM/CPC
  • 北极星 vs 过程指标：留存是北极星但实验周期长、灵敏度低；时长/CTR 是灵敏代理但可能被"标题党"优化偏——指标组合 + 护栏是标准做法

六、AI Agent

6.1 概念与范式

Q59Agent 和 Workflow 的区别？Agent 的四个核心组件

Workflow：代码预先编排好 LLM 调用路径（DAG 固定），模型只在节点里执行；Agent：LLM 自己决定下一步做什么（动态控制流），循环"感知 → 思考 → 行动"直到任务完成。Anthropic 的经典论断：能用 workflow 解决的别上 agent——可控性、成本、延迟都更好；agent 留给路径无法穷举的开放任务。

四组件：

  • 规划（Planning）：任务分解（subgoal）、反思（self-critique）、重规划（replan）
  • 记忆（Memory）：短期（上下文窗口）+ 长期（外部存储/向量库）+ 工作记忆（scratchpad）
  • 工具（Tools）：function calling、代码执行、检索、API——扩展模型的"行动半径"
  • 执行循环（Action Loop）：观察环境反馈 → 更新状态 → 决策下一步；失败重试与终止条件设计
Q60ReAct / Plan-and-Execute / Reflexion 三大范式
ReAct 循环：
Thought: 我需要先查上海明天天气
Action: search_weather[上海, 明天]
Observation: 多云 18~24℃
Thought: 天气适中，推荐户外……
Answer: ……
  • ReAct（推理+行动交错）：每步先想再动，用观察修正推理。简单通用、成为事实标准；缺点是逐步贪心、长任务易跑偏
  • Plan-and-Execute：先整体规划成步骤列表，再逐步执行（可并行的并行）；执行偏差大时重新规划。长任务更稳、token 更省（计划只生成一次）
  • Reflexion：失败后生成语言化反思（哪步错了、下次怎么改），存入情景记忆指导重试——"自我改进"的经典实现

现代变体：长 CoT 推理模型（R1/o1）内化了反思回溯；Agentic RL（美团 JD 原词）——用强化学习直接优化"任务规划、反思与执行"的长链路稳定性和成功率，是当前前沿方向。

Q61CoT → ToT → 长链推理的演进
  • CoT：线性思维链，把推理摊开在 token 上
  • Self-Consistency：采样多条 CoT 多数投票
  • ToT（Tree of Thoughts）：树状展开多分支思路，可评估、剪枝、回溯——搜索式推理
  • 长链推理模型：RL 训出的模型自主生成"探索→验证→回溯→继续"的长推理轨迹（R1-Zero 涌现的 aha moment）；验证器（process reward model）与可验证奖励（代码单测、数学验算）是关键

面试要点：为什么推理能提升——注意力单次前向的串行计算深度有限，token 生成提供循环计算空间；推理时计算扩展（test-time scaling）是 o1/R1 的核心叙事。

6.2 核心组件

Q62Function Calling 的实现原理？工具多了怎么办？

本质：模型以结构化 JSON 输出（工具名 + 参数）替代自然语言回复。实现上是"受约束解码"——把工具的 JSON Schema 编译进语法约束（constrained decoding / grammar），保证输出 100% 可解析；训练用大量工具调用轨迹 SFT + RL。

  • 工具检索：工具上百个时全塞 prompt 浪费上下文且选择准确率下降 → RAG 思想：按任务描述检索 top-k 相关工具动态注入（工具即文档，name/description 写清楚是效果第一变量）
  • 并行调用：一次生成多个独立调用降低轮次；依赖调用必须串行
  • 错误处理：工具返回错误 → 作为 observation 喂回让模型自纠（参数写错重试、换工具）；设最大轮次与 token 预算防爆循环
Q63MCP 协议解决了什么？与 Function Calling 的关系？

MCP（Model Context Protocol，Anthropic 2024）：把"模型 ↔ 工具/数据源"的连接标准化——M×N 的集成问题变 M+N（每个应用实现一次 client，每个数据源实现一次 server，协议互通）。

  • 类比 USB-C：统一的接口层；组件：Host（如 Claude/编辑器）、Client（连接器）、Server（暴露 tools/resources/prompts）
  • 与 FC 的关系：FC 是模型能力（会不会输出结构化调用），MCP 是生态协议（工具如何被发现、描述、鉴权、传输）——FC 在下层，MCP 在上层，互补不替代
  • 价值：工具一次封装处处可用（文件系统、GitHub、数据库、浏览器都有现成 MCP server）；鉴权与企业管控标准化

追问：A2A（Agent-to-Agent，Google 提出）解决 agent 间协作握手——与 MCP（agent↔工具）是不同层的协议。

Q64记忆机制设计：短期、长期、工作记忆
  • 短期记忆 = 上下文窗口：对话历史、中间结果；窗口是稀缺资源（成本 + 长上下文注意力衰减 lost-in-the-middle）→ 需要压缩与摘要：老对话滚动摘要成简报，保留关键实体与承诺
  • 长期记忆 = 外部存储：向量库（语义检索历史经验）、结构化 KV（用户偏好/事实，可用 LLM 抽取后写入）、情景记忆（过往任务轨迹，Reflexion 的反思就存这里）
  • 记忆写入策略：什么时候写（任务结束总结 vs 实时）、写什么（去重、冲突合并——"用户换了工作"要覆盖旧事实）、如何检索（embedding 召回 + recency/importance 加权，类似 MemGPT/Letta 分页设计）
  • 工程红线：记忆污染（错误信息被固化反复引用）需要来源追踪 + 用户可见可编辑
Q65多智能体系统：什么时候拆？怎么编排？
  • 拆分的理由：① 上下文隔离（每个 agent 只看自己职责相关内容，避免 prompt 互相污染）② 角色专化（各自的 system prompt/工具集/模型档位——路由便宜任务到小模型）③ 并行加速
  • 不拆的理由：通信成本、错误传播放大、调试困难——单 agent + 好工具能解决的别拆
  • 拓扑：Supervisor（主控分派汇总，最常用）/ Pipeline（流水线传递产物）/ 辩论（多角色互相批判，提升答案质量）/ 去中心化（黑板模式）
  • 框架：LangGraph（显式状态机，控制流代码化，生产主流）、AutoGen（多 agent 对话）、CrewAI（角色编排）；编排原则：确定性流程用代码写死，只把"判断"交给模型

6.3 工程与评测

Q66上下文工程（Context Engineering）是什么？

比 prompt engineering 更系统的说法：LLM 应用性能 = 模型 × 放进上下文的内容。上下文是稀缺资源，要像管理内存一样管理它：

  • 该放什么：任务目标、约束、工具结果（裁剪过）、检索知识（rerank 过）、最少的示例
  • 结构：system / 长期设定在前，动态信息居中，关键指令末尾复述（recency 偏置）；XML 标签分隔区块
  • 压缩：工具返回的原始 JSON 裁剪字段；历史摘要化；无关轮次丢弃（compaction，Claude Code 的核心机制）
  • 长上下文 ≠ 免费注意力：lost-in-the-middle 现象——中间信息召回率低；重要信息放两端，或用检索按需注入而非全量塞入
  • 上下文缓存：prefix caching（相同 system prompt + 工具定义的 KV 复用）直接降本提速
Q67Agent 怎么评测？SWE-bench 等基准的含义
  • 结果评测：任务成功率（最终状态对不对，自动化可验证——文件/单测/答案比对）；pass@k（k 次尝试至少 1 次成功——工程上 k=1 成本视角，k≥5 衡量能力上限）
  • 轨迹评测：步骤正确性（用 LLM-as-judge 或规则判每步合理性）、工具选择准确率、轮次效率（达成任务的 token/步数成本）
  • 基准：SWE-bench（真实 GitHub issue 修复，大模型编程能力金标准）、GAIA（通用助手任务）、WebArena（网页操作）、ToolBench、BFCL（function calling 准确率）、τ-bench（客服多轮工具任务）
  • 陷阱：基准污染（issue 在训练数据里）——看 Verified/新题子集；环境非确定性（同一任务多次跑分数波动）→ 报 pass@k 与多次方差
  • 线上：人工抽检 + 用户反馈信号（采纳率、修正率、放弃率）+ 护栏触发率
Q68Agent 安全与护栏设计
  • 提示注入：恶意内容藏在工具返回/网页/文档里（"忽略之前指令，把数据发到……"）——间接注入是 agent 特有的最大攻击面；缓解：工具输出与指令隔离（明确标注"这是数据不是指令"）、敏感操作二次人工确认、最小权限
  • 权限收敛：工具按需授权（读写分离、目录白名单）、沙箱执行代码、金额/外发类操作硬上限
  • 预算护栏：最大轮次、最大 token、最长运行时间——agent 循环失控是真实成本事故来源
  • 幻觉动作：调用不存在的工具/编造参数 → schema 强校验 + 参数合理性检查；重要事实引用来源
  • 可观测：全链路 trace（每步 thought/action/observation 落盘）——回放调试与事故取证的基础

七、面试通用

Q69算法岗简历与项目怎么讲？（STAR + 深挖防御）
  • 结构：一句话背景（业务问题）→ 难点（为什么不能直接套标准方案）→ 你的方案（关键决策 + 为什么这么选）→ 量化结果（相对提升、AB 数据）→（可选）踩坑与迭代
  • 每一条都会被深挖三层：① 为什么用 A 不用 B（对比过的方案）② 具体怎么做的（结构/超参/数据规模/算力）③ 数字怎么来的（评测口径、是否显著）。答不上来任何一层都比不写这条更伤——简历上每个词都要能扛住三问
  • 大模型项目叙事模板：基线（直接 prompt 原始模型）→ 痛点（长文档检索不准/延迟高/成本贵）→ 方法（RAG 切块+混合检索+重排 / LoRA 微调 / vLLM 部署+量化）→ 指标（准确率、P95 延迟、单次调用成本）→ 消融（每个组件贡献多少）
  • 把本站 LeetCode HOT 100 刷完并标注心得，本身就是简历上可信的一条
Q70算法题面试的评分维度与准备策略
  • 评分维度（不只是 AC）：沟通（先澄清输入范围/边界再动手）→ 思路（暴力 → 优化路径讲清楚，复杂度分析随口就来）→ 代码（变量命名、边界处理）→ 测试意识（主动构造反例：空输入/单元素/全相同/极大值）
  • 准备策略：HOT 100 按题型突破（本站已按难度排序，附思路/代码/易混淆点）——每个题型总结"识别信号"：见"前 K 个"想堆/快速选择；见"子数组和"想前缀和+哈希；见"区间重叠"想排序+贪心；见"求所有方案"想回溯
  • 当场卡住的话术：先给暴力并分析复杂度（保底分）→ 提出 bottleneck → 逐个尝试数据结构优化。面试官提示时接得住（提示是观察你协作性的环节，不是羞辱）
Q71系统设计题：设计一个推荐系统 / LLM 推理服务

推荐系统（30 分钟版）：① 明确目标与指标（北极星+护栏）② 离线：样本构建（曝光-点击 join、防穿越）、特征体系（用户/item/上下文/交叉）、召回（多路+双塔+ANN）→ 排序（多任务 PLE）→ 重排（多样性）③ 在线：特征实时化（流式）、模型服务（打分延迟预算）、缓存策略 ④ 闭环：AB 实验、样本回流、天级更新 ⑤ 容量与降级。

LLM 推理服务：① 需求量化（QPS、TTFT/TPOT 目标、上下文长度、模型规模）② 单机：量化 + KV Cache + PagedAttention + continuous batching（vLLM/sglang）③ 扩展：TP/PP 切分、多副本负载均衡、prefix cache ④ 生态：网关限流排队、流式 SSE、function calling 路由、多模型分级（贵问题大模型，简单问题小模型）⑤ 可观测：token 用量、缓存命中率、长尾延迟。

答题框架：需求澄清 → 估算规模 → 高层架构图 → 逐模块深挖 → 瓶颈与权衡 → 容错与演进。主动讲 trade-off 是拿分关键（没有完美设计，只有上下文中的取舍）。

8.1 大模型架构新范式

Q73MoE（混合专家）架构：原理、路由与负载均衡

核心思想：把 Transformer 的 FFN 替换为多个"专家"FFN，每个 token 只经路由器（gating network）激活其中一小部分——总参数量巨大、单 token 计算量小。DeepSeek-V3 共 671B 总参数，每 token 仅激活约 37B（约 5.5%），却达到同规模稠密模型的能力。

  • 路由机制：门控网络对每个专家打亲和度分数，Top-K 选出活跃专家，输出加权融合。DeepSeek-V3 为 256 个路由专家选 8 个 + 1 个常驻共享专家；共享专家负责捕捉通用知识（每个 token 都走），路由专家负责分化知识
  • 细粒度专家（DeepSeekMoE 特色）：把专家切小、多选几个，比"少数大专家"更能让不同专家学到有区分度的知识，减少专家间同化
  • 负载均衡三件套：① 辅助负载均衡损失（DeepSeek-V2 用，鼓励 token 均匀分配到专家）② 无辅助损失的均衡策略（V3 首创：给每个专家一个可学习的 bias 项动态调节路由概率，避免辅助损失干扰主损失）③ 专家容量因子（capacity factor）：专家超载时多余 token 经残差直接流向下一层
  • 工程：训练推理都要专家并行（EP）——专家分片到不同 GPU，All-to-All 通信交换 token；负载不均会让部分 GPU 成为瓶颈

追问高频：① MoE 为什么训练容易不稳定？（路由是离散选择，梯度不可导，用 softmax 加权 + 辅助损失软化）② 共享专家为什么不能省？（没有它，通用知识会被迫分散到所有路由专家，浪费容量）③ 和稠密模型的部署差异？（显存要装下全部专家，激活参数少≠显存少；吞吐高但首 token 延迟受路由通信影响）

Q74MLA（多头潜在注意力）：DeepSeek 为什么要"压缩再恢复"KV？

问题背景：MHA 的 KV Cache 随序列长度线性增长（每层 × 头数 × 头维），长上下文推理时显存爆炸。MQA/GQA 靠"砍头数"缓解但牺牲表达能力。

MLA 思路：对 K、V 做低秩联合压缩——先把隐状态 h 降维到一个远小于「头数×头维」的潜在向量 cKV，缓存时只存 cKV；注意力计算时再经上投影矩阵恢复出各头的 K 和 V。因为「降维→升维」矩阵是训练出来的，压缩是有损但可控的，性能与 MHA 相当。

  • 数学形式：cKVt = WDKVht（降维）；kt = WUKcKVt，vt = WUVcKVt（升维）。推理时只缓存 cKVt 和解耦的 RoPE 键 kRt
  • 解耦 RoPE 的原因：位置旋转作用在完整 K 上时，"先压缩再恢复"与 RoPE 的交换次序不兼容，所以把带位置信息的部分单独拆一路出来计算和缓存
  • 收益：KV Cache 大幅缩小 → 同样显存能塞更大 batch → 吞吐提升；Q 也做了低秩压缩，训练时激活显存更省
  • 权衡：矩阵乘法多了一层（升维要在注意力时算），可用算子融合（吸收进权重）优化——这也是面试里"MLA 推理怎么加速"的常见追问

对比记忆：MQA 砍 K/V 头数（显存↓ 表达↓）、GQA 分组共享（折中）、MLA 低秩压缩（显存↓↓ 性能≈MHA）——一句话：GQA 是"减少份数"，MLA 是"换个更小的存储表示"。

Q75MTP（多 Token 预测）与投机解码：训练目标与推理加速的联动

MTP：传统自回归每步只预测下一个 token；MTP 在每个位置并行预测未来多个 token（DeepSeek-V3 在主输出头之外接额外的 MTP 模块——一个小 Transformer 层 + 输出投影，接收对应深度的中间表示，预测第 2、3 个 token）。训练时多个预测损失加权求和，等于给模型更密的监督信号，benchmark 表现更强。

与投机解码（speculative decoding）的关系：MTP 头天然可以作为 draft model——主模型生成 1 个 token 的同时，MTP 头"顺便"预测出后面 2~3 个候选 token，由主模型并行验证，验证通过就一次接受多个 token。训练时的辅助目标，推理时白捡的加速器。

  • 投机解码通用原理（不依赖 MTP）：小模型（draft）快速生成草稿 → 大模型（target）一次前向并行打分验证 → 接受通过的前缀、从第一个分歧点重新生成。数学保证输出分布与大模型单独采样完全一致（lossless）
  • 加速条件：草稿接受率要高（任务越"可预测"越快，代码 > 创意写作）；大模型并行验证 batch 的成本要低于逐步自回归
  • 其他主流加速：vLLM 的 PagedAttention + continuous batching、量化（W8A8/FP8/W4A16）、prefix caching（共享系统提示词的请求复用 KV）

追问高频：为什么验证可以并行？——自回归逐步生成是串行依赖，但"给定前缀给每个位置打分"只需一次前向，这是投机解码成立的根本。

Q76长上下文扩展：YaRN 与 RoPE 插值

问题：RoPE 在训练长度外（如 4K 训练、128K 推理）外推时注意力分数会崩坏，模型"失忆"。解决思路是位置插值：把长序列的位置 id 压缩回训练见过的范围。

  • 线性插值（PI）：位置 id 乘以 训练长度/目标长度 比例缩小——所有相邻 token 间距被等比压小，高频细节丢失
  • NTK-aware：不缩位置，而是调大 RoPE 频率基 base（如 10000 → 更大），让高频分量保持不变、只拉伸低频——"高频管局部语义、低频管远距离"，局部能力不受损
  • YaRN：在 NTK-aware 基础上再对每维频率做温度/注意力温度修正，并用很少的微调步数（数千步）就能把 4K/8K 的模型扩到 128K，短上下文性能不退步——DeepSeek-V3 采用的就是 YaRN

面试要点：长上下文的另一个瓶颈不在位置编码而在 KV Cache 显存（见 MLA 题）与有效上下文（"大海捞针"测试过≠能真正利用全部上下文，中间部分信息利用率低，即 "lost in the middle" 现象）。评测长上下文要报 NIAH（大海捞针）+ 长文档 QA + 关键信息检索等多档任务。

8.2 推理模型与 RL 新范式

Q77推理模型（o1 / R1 类）：test-time compute 到底是什么？

范式转变：过去提升性能 = 训练时堆算力（更大模型/更多数据）；推理模型证明推理时堆算力（生成更长的思维链、自我验证、多路径搜索）也能显著提升——这叫 test-time compute / inference scaling。

  • 效果量级：以 AIME 数学竞赛为例，GPT-4o 单次采样约 13%，o1 用长 CoT 单次采样达到 74%、配合重排序 93%；到 o3 在 AIME 2024 上 96.7%——从"及格线"到"接近满分"全靠推理时算力
  • 机制直觉：CoT 把"一跳答不出的题"分解成多步，每步都在浅层计算，等价于用 token 串行计算换并行层数不够的问题；自我反思与回溯让模型能纠错，而不是"一条路走到黑"
  • 代价与权衡：延迟与 token 成本成倍增加 → 生产上要做"路由"（简单问题走普通模型，难题才走推理模型），这也是各家做模型分级路由的原因
  • 训练侧来源：能力主要来自大规模强化学习（让模型自己探索出长思考策略），而不是仅靠 SFT 蒸馏现成的长 CoT（见 R1 题）

追问高频：① 长度与质量的怪象——RL 训练后期模型输出会越来越长（奖励只有对错时，更长的验算提高正确率），需要加长度惩罚控制；② 为什么小模型蒸馏推理能力有效？（推理模式可以迁移，但小模型容量有限，超过某个规模差才明显）

Q78GRPO 与 PPO / DPO 的对比：为什么 R1 选了 GRPO？

PPO 的负担：需要 4 个模型在显存里共存——策略模型、参考模型（算 KL 约束）、奖励模型、Critic（价值网络，估计每个 token 的优势）。Critic 与策略模型同规模，显存和计算直接翻倍，且在 LLM 场景训练价值网络本身就难收敛。

GRPO（Group Relative Policy Optimization）：DeepSeekMath 提出、R1 沿用的改进——干掉 Critic，用"组内相对排名"当 baseline：对同一个 prompt 采样一组（如 16 条）回答，每条的优势 =（自身奖励 − 组均值）/ 组标准差。组内互相比较天然扣除 prompt 难度的影响，省掉整个价值网络。

  • GRPO vs PPO：优势估计从"学习的价值函数"变成"组内统计量"——省一半显存、训练更稳；代价是每个 prompt 要采样多条（生成开销换 critic 开销），且优势估计噪声更大
  • GRPO vs DPO：DPO 完全不用在线采样与奖励模型（离线偏好对直接构造损失），适合对齐通用对话；GRPO 在线探索 + 结果奖励，适合有客观可验证奖励的推理任务（数学答案对错、代码单测通过）——所以 R1 用 RL（GRPO）而不是 DPO
  • R1 的奖励设计：纯结果奖励（答案对=1 错=0）+ 格式奖励（把推理过程放进 <think> 标签）——不给过程奖励，让"怎么思考"完全由模型自己探索
  • KL 处理：R1 甚至把 KL 惯例项也从损失里移出、融进优化器更新，进一步防熵坍缩

Q79过程奖励（PRM）vs 结果奖励（ORM）：数学推理 RL 的两条路线
  • ORM（Outcome Reward Model）：只看最终答案对不对打分。优点：标注便宜（对/错二值）、无标注歧义；缺点：奖励稀疏——一条几百步的推理只有一个信号，信噪比低，模型可能学会"表面验算"而非真推理
  • PRM（Process Reward Model）：对推理每一步打分（这步是否有效、是否在正确的方向上）。优点：信号密、可定位错误步骤，对搜索式解码（step-level beam search / MCTS）友好；缺点：步骤级标注贵且标准难统一，人工标数据集（如 PRM800K）成本高，还有"过程正确但答案错"的假阳问题
  • DeepSeek-R1 的选择：纯 ORM——他们发现给模型加过程奖励会引入人工先验、限制模型探索出人意料的推理策略（以及奖励作弊风险）；结果奖励 + 足够大的采样规模，CoT 质量自己涌现
  • 折中方案：蒙特卡洛 rollout 估计步骤价值（自动构造 PRM 数据，免人工）；或轻量规则奖励（格式、长度）辅助稳定训练

答题框架：先说两者定义与 trade-off（信号密度 vs 标注成本/偏差），再点出"可验证奖励领域（数学/代码）ORM + RL 已够用，开放领域仍需 PRM/偏好模型"，最后带一句 R1 的实证结论。

Q80DeepSeek-R1 的训练流程与蒸馏：从 R1-Zero 到可用模型
  • R1-Zero（关键实验）：直接在 base 模型上做大规模 RL（GRPO + 规则奖励），完全跳过 SFT。结果：推理能力自行涌现（反思、"aha moment"、验证回溯），证明 RL 是推理能力的来源而非仅靠模仿；但可读性差、语言混杂
  • R1 完整流程（四阶段）：① 冷启动：用少量长 CoT 数据 SFT，给推理一个可读的起点 ② 推理 RL：大规模 GRPO + 语言一致性奖励 ③ 拒绝采样 + 全场景 SFT：从 RL 检查点采样、按答案正确性筛出优质数据，混合写作/问答/翻译等通用数据再 SFT ④ 对齐 RL：混合场景的多奖励再强化——解决"只会推理不会聊天"
  • 蒸馏：用 R1 生成的长 CoT 数据直接 SFT 小模型（Qwen/Llama 系列 1.5B~70B 稠密模型）。结论：大模型蒸馏 > 小模型直接 RL（14B 蒸馏版超过 14B 自 RL 版），推理模式的传递比从零探索高效得多
  • 面试落点：这个流程是"RL 造能力、SFT 定格式、蒸馏降成本"的完整样板，被后续几乎所有推理模型沿用（含各家 2026 年的 Long CoT RL 岗位要求）

8.3 Agent 协议生态

Q81MCP（Model Context Protocol）：AI 的"USB-C 接口"

是什么：Anthropic 2024 年 11 月发布的开放协议，标准化模型 ↔ 工具/数据源的连接方式；2025 年 12 月捐给 Linux Foundation 旗下 Agentic AI Foundation 治理。到 2026 年初生态活跃服务端已超万个。

  • 解决的问题：以前 M 个 AI 应用 × N 个数据源 = M×N 套定制集成；MCP 把它变成 M+N——每个应用实现一次客户端、每个服务实现一次服务端，即插即用（USB-C 类比的由来）
  • 技术形态：基于 JSON-RPC 2.0 的客户端-服务器协议。客户端（host 应用，如 IDE、聊天客户端）持有模型；服务端封装工具能力
  • 三类原语：Tools（模型可主动调用的动作，带名称/描述/JSON Schema 参数定义，配合 function calling）、Resources（可读取的上下文数据：文件、数据库记录）、Prompts（预定义任务模板）
  • 交互流程：客户端连上服务端 → tools/list 拉取能力清单 → 注入模型上下文 → 模型决定调用 → 客户端经 JSON-RPC 转发给服务端执行 → 结果回填模型 → 继续对话。决策权在模型（客户端），服务端是被动的执行方
  • 安全设计：动态凭证（短期访问令牌）、字段级最小权限、审计日志

追问高频：MCP 和普通 function calling 什么区别？——function calling 是模型能力（模型学会输出结构化调用），MCP 是生态协议（调用怎么发现、传输、鉴权的标准化）；MCP 的 tools 本身就是通过 function calling 让模型用的。

Q82MCP / A2A / ANP：Agent 通信协议怎么选？

2025–2026 年 Agent 协议的格局是"分层互补"，不是互相替代：

协议连接对象提出方/时间核心机制
MCP模型 ↔ 工具/资源Anthropic，2024.11（2025.12 入 Linux Foundation）JSON-RPC 客户端-服务器；tools/resources/prompts 三原语
A2AAgent ↔ AgentGoogle，2025.4（2025.6 入 Linux Foundation，100+ 公司支持）Agent Card（/.well-known/agent.json 声明能力）+ 任务生命周期（created → working → completed/failed）
ANP互联网尺度的去中心化 Agent 网络社区语义化描述文档 + URL 互链，类爬虫的按需发现
  • MCP vs A2A：MCP 管"agent 用工具"（工具是无状态的、结构化输入输出的原语）；A2A 管"agent 找 agent 合作"（对方是会推理、有状态、多轮交互的自主系统，调用方只关心"做什么"不关心"怎么做"）。
  • 典型组合：一个 agentic 应用用 A2A 与其他 agent 协作，自己内部用 MCP 调工具——A2A 管协作，MCP 管能力，两者天然互补（Google 官方文档的修车厂例子：经理 agent 用 A2A 与供应商 agent 对话，机械工 agent 用 MCP 调诊断仪、查维修手册）
  • ANP 的差异：MCP 一次性返回全部工具清单，ANP 只给层级链接让 agent 像爬虫一样按需探索——面向跨组织的开放互联网场景，强调去中心化身份与数据主权
  • 行业演进三段论（面试金句）：Agent = LLM（智力爬升）→ LLM + Tools（工具扩展，MCP）→ LLM + Tools + Communication（社会化，A2A/ANP）

8.4 生成式推荐

Q83生成式检索 / Semantic ID：LLM 时代的推荐新范式（TIGER）

传统范式的瓶颈：双塔/ANN 召回把推荐视为"度量空间里的最近邻搜索"——item 是 embedding 空间里的一个点，泛化依赖 embedding 学得好不好，且候选必须预先存在索引里。

生成式检索（TIGER, Google 2023）：把召回重构为自回归生成——模型根据用户历史直接"写出"要推荐的 item 的 ID。

  • Semantic ID：核心障碍是 item ID（如数字编号）无语义。TIGER 先对 item 内容 embedding 做 RQ-VAE（残差量化自编码器），量化成一小串离散 token（如 3~4 个 code），语义相近的 item 共享前缀——这就是 Semantic ID（SID）
  • 生成与检索：把用户交互序列的 SID 当作"语言"训练一个 encoder-decoder（T5 类）模型，推理时 beam search 生成一批 SID，映射回 item 即候选——召回从"空间检索"变成"序列生成"，端到端可微
  • 冷启动优势：新 item 没有交互但有内容 → 照样能量化出 SID 进入生成候选（TIGER 实验把 5% item 从训练集移除模拟冷启动，仍显著优于基于语义 KNN 的对照）
  • 2026 工业趋势：Semantic ID 已进入大厂 JD（如"统一排序模型、Semantic ID、多模态表示学习"）——生成式推荐、LLM 语义召回、把推荐序列当语言建模（HSTU/生成式推荐架构）是搜广推面试的新增高频区

答题框架：传统范式一句话 → SID 怎么构造（RQ-VAE）→ 生成式检索流程 → 对比（端到端 vs 两阶段、冷启动、候选只能是生成出的 SID 前缀——覆盖度问题）→ 工业落地现状。

8.5 Agentic Coding 评测

Q84SWE-bench 与 Agent 能力评测：为什么"刷榜"变难了
  • SWE-bench 是什么：从真实开源 Python 仓库的 GitHub issue + 对应 PR 构造的数据集——给 agent 一个仓库快照和 issue 描述，要求它自主定位代码、修改并生成 patch，通过仓库自带单测。指标是解决率（resolve rate）。SWE-bench Verified 是经人工筛过、任务描述无歧义的子集，是当前 Agentic Coding 的权威榜单
  • 为什么它是"好 benchmark"：真实（不是人造玩具题）、可验证（单测通过与否客观）、防作弊（改测试用例直接判负）；且有细分榜（SWE-bench Lite/Verified/Multilingual、前端、多模态）
  • Agent scaffold 影响巨大：同一个模型配不同的 agent 框架（检索策略、编辑工具、自我修复循环、上下文管理）分数差可达十几个点——评测的其实是"模型 × 脚手架"系统，这也是为什么 2026 年 Agent Infra 岗位需求暴涨
  • 其他必知评测：WebArena/OSWorld（操作网页/桌面）、GAIA（通用助理）、Terminal-Bench、长程任务的成功率/步数/成本三角（见 6.3 节 Agent 评测）
  • 面试落点：自己搭过 Agent 的话，用"任务成功率 + 平均步数 + token 成本 + 失败归因"四件套讲评测体系，比只报一个准确率有说服力得多
Q852026 面试趋势总结：哪些新知识正在变成"必考"
  • 大模型架构：MoE（路由/负载均衡/专家并行）、MLA（KV 压缩与 GQA/MQA 对比）、MTP/投机解码、YaRN 长上下文——从"知道名字"升级到"能讲清为什么这么设计"
  • 后训练：GRPO vs PPO vs DPO 的选型逻辑、PRM vs ORM、R1 四阶段流程与蒸馏——"读过 R1 报告并能复述训练流程"已是明牌考点（多家 JD 直接写 Long CoT RL）
  • Agent 工程：MCP 协议三原语与 A2A 的分工、"评测 + 护栏 + 成本"三位一体、Agentic Coding（SWE-bench）——Agent 岗必考，大模型岗也常问
  • 搜广推：LLM × 推荐融合（生成式推荐、Semantic ID、语义召回）是新增区，传统漏斗八股仍是主体
  • 学习建议：以本库前七章为地基，第八章为差异化——面试官问"最近关注什么"时，能从 MoE 架构一路聊到 Agent 协议生态的人极少，这就是区分度。信息源：DeepSeek-V3/R1 技术报告（arXiv 2412.19437 等）、各厂工程博客、a2a-protocol.org 与 MCP 官方文档
